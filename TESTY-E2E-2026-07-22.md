# Testy wtyczki AMPER LAS dla WooCommerce - raport 2026-07-22

Srodowisko: WordPress+WooCommerce (Docker, http://localhost:8003) + las-backend (:8001),
sklep LAS "Demo WooCommerce" (TrackedSite 27). Testy przegladarkowe: claude-in-chrome
(sklep) + chrome-devtools (konsola LAS, iframe czatu przez CDP).

## Warstwa 1 - testy backendowe wtyczki (wp-cli): `dev/tests/test-plugin.php`

**78/78 PASS.** Zakres: formatowanie kwot (2 miejsca, format sklepu, bez NBSP); payload
produktu (klucze b2c, wariant = id wariacji, brak zdjecia/SKU/ceny -> ""); payload koszyka

page_ping/select_item, logo tylko na session_start); guardy dispatch; automat outboxa
(pending -> sent potwierdzone, brak konfiguracji NIE zuzywa prob, martwy cel -> failed po
8 probach, sent nie wysylany ponownie); deduplikacja purchase (2x order_processed -> 1
event, meta + visitor_id w zamowieniu).

## Bledy znalezione przez testy i NAPRAWIONE

1. **Proxy REST kasowalo kupony klienta.** `wc_load_cart()` w REST ladowal pusty koszyk
   i przy zamknieciu zadania zapisywal sesje - pozycje przezywaly w persistent cart,
   ale `applied_coupons` byly nadpisywane pusta lista (repro: kupon znikal przy wejsciu
   w checkout; bez wtyczki nie znikal). Fix: odczyt sesji WooCommerce READ-ONLY
   (`WC_Session_Handler->get_session()` bez `init()`, wiec bez hooka zapisu); snapshot
   koszyka dla eventow przegladarkowych budowany z surowych wierszy sesji
   (line_total+line_tax, czyli PO rabatach - jak w b2c).
2. **select_item z wyszukiwarki mial liste "Shop"** - w Woo `is_shop()` jest true takze
   na wyszukiwarce produktow; `is_search()` musi byc sprawdzane wczesniej.
3. **add_shipping_info: koszt/etykieta stawki flaky** - hook update_order_review odpala
   sie zanim Woo przeliczy pakiety; teraz najpierw `calculate_totals()`, potem
   label+koszt Z WYBRANEJ STAWKI (nie ze starego cart total).
4. **Produkt bez ceny wysylal "0.00"** zamiast "" (parity z b2c).
5. **Brak eventow przy zmianie ilosci w koszyku** - dodany hook
   `woocommerce_after_cart_item_quantity_update` (delta>0 -> add_to_cart, delta<0 ->
   remove_from_cart).

## Znane, swiadome roznice wzgledem b2c

- Cart.total = wartosc pozycji (po rabatach, z VAT) BEZ wysylki; purchase.total = pelna
  kwota zamowienia (jak w b2c).
- `metadata.client_ip` przy braku zgody: las-backend sam backfilluje IP NADAWCY (serwera
  sklepu) - zachowanie identyczne dla b2c, nie wyciek PII.
- Dwa adresy LAS (serwerowy/publiczny) - tylko dla srodowisk typu Docker; w produkcji
  jedno pole.
